> the recovery surface reachable over the serial DEBUG console, and how does it differ from the JACE-8000?

>
> **Bottom line for the operator:** besides the normal **ATLAS System Shell** menu [Block 657], the DEBUG
> serial port fronts **three recovery surfaces, and NONE of them is read-only** — all mutate or wipe the
> controller. (1) A **pre-boot Boot Options menu** (press ESC during boot) with only **two** choices. (2)
> **Platform Access Recovery** — regain access with no valid credentials/passphrase WITHOUT losing station
> data, gated by a **Tridium-signed Reset Authorization Key** (24-hour token). (3) The **SHUT-DOWN button
> factory-defaults wipe**, which **deletes all platform and station data**. Plus a **passphrase-mismatch
> menu** on decrypt failure. Do not enter these paths during read-only exploration.

## §658.1 — The Boot Options menu (press ESC during boot)

`[CERT-doc]` The JACE-9000 exposes a pre-boot menu on the serial console, entered by pressing **ESC** early
in the boot sequence:

- "Power up the controller and during the boot sequence, press Esc when you see the following message:
  `Press ESC to enter boot options...`." — `J9Startup/J9ResetPlatformCredentials.txt:74`
- The menu has exactly **two** options:
  `Boot Options` / `1 Reset platform credentials` / `2.Continue with boot` / `Enter Choice :`
  — `…J9ResetPlatformCredentials.txt:76-79`

Timing quirk (`[CERT-doc]`): "You have just a few seconds to press the Escape key. If you press Esc too
late, you will not get the Boot Options menu…" (`:61`), and if Esc is pressed after the menu appears "the
system will ignore further input until an alphabetic character is entered (for example, the letter 'a')"
(`:63`) — enter any non-numeric character to exit that escape mode, then delete it (`:68`).

This is the sharpest structural difference from the JACE-8000, whose **Alternate Boot Options** menu had
**eight** entries ([Block 463] §463.2). The JACE-9000 collapses the pre-boot surface to reset-or-continue.

## §658.2 — Platform Access Recovery (Boot option 1): Tridium-signed, keeps station data

`[CERT-doc]` Selecting `1 Reset platform credentials` (then `Y`) starts **Platform Access Recovery** — the
supported way to regain access to a functional controller when you have "no valid credentials or system
passphrase … due to a change in building ownership or control contractors," and it does so "**without
losing station data and configuration**" (`…J9ResetPlatformCredentials.txt:13-15`).

The flow is a challenge/response signed by Tridium:

1. The screen prints the controller's **Host id** and a **randomly generated Token** + `Key version`:
   `Host id : ATLAS-SD-…` / `Token : AE85-…` / `Key version: 1`, and states **"Token is valid for 24
   hours"** (`:89,91,93,96`).
2. You contact your Support channel / Tridium with the **Host id + Token + a customer name** and establish
   **"proof of ownership"** (`:108-118`).
3. Tridium "validates your customer identity via **Niagara Licensing**, and generates a **'Signature'** for
   the token/Host id/customer name that includes a **Reset Authorization Key**" (`:122`); the key is valid
   only 24 hours (`:124`).
4. You enter the key **Single line** (paste from email) or **Multiple line** (over voice), then `v` to
   verify (`:128-131`).
5. **The controller uses the previously-installed Tridium certificate to verify that this Signature was
   generated by [Tridium's] private key** for the given token/Host id/customer name (`:139`). Only then does
   "the system software generate the factory default username/password credentials and default system
   passphrase" (`:140`), print `Verification Passed` / `System user credentials are reset` /
   `Shutdown in 10 seconds` (`:143-146`), and reboot.

This is the **same cryptographic recovery model as the JACE-8000** ([Block 463]): recovery ≠ bypass — it
requires an offline, Tridium-signed authorization bound to the unit's Host id, and it is rate-limited by a
24-hour token. It **regenerates factory defaults** (so on next connect you are forced to set new
credentials + passphrase) but it does **not** wipe the station. The Host-id binding is exactly why the
`ATLAS-SD-…` identity ([Block 657] §657.1) matters: the signature is scoped to that hardware id.

## §658.3 — Factory Defaults: the SHUT-DOWN button wipe (destructive)

`[CERT-doc]` A second, DESTRUCTIVE recovery exists via a physical button:

- "The process of recovering factory defaults **deletes all platform and station data**, and returns the
  controller to the state it was in when it shipped from the factory." — `RestoringFactoryDefaults-36768467.txt:13`
- "CAUTION: Recovering factory defaults removes all platform and station data from the device." (`:46`)
- The **SHUT DOWN button** is the trigger: "SHUT DOWN shuts down the controller and **serves as the factory
  defaults recovery button**" (`:61`); "STAT (status LED) blinks during recovery of factory defaults" (`:66`).
- Prerequisite: "You have **administrator-level platform credentials**" and a backup (`:27`).

So the two recovery routes bracket the trade-off: **Platform Access Recovery keeps data but needs Tridium's
signed key**; **Factory Defaults needs no Tridium key but destroys everything** (it is also the documented
**decommissioning** wipe). Both are reached over the DEBUG console; neither is a read-only action.

## §658.4 — The passphrase-mismatch menu (System Decrypt Failure)

`[CERT-doc]` When the system passphrase does not match the encrypted data (e.g. after restoring a portable
backup with a different passphrase — [Block 466]), a serial login lands on a distinct menu:

- "Make a serial connection to the unit's DEBUG port." (`ResolvingAPassphraseMismatch-346D4B94.txt:39`)
- "The **System Decrypt Failure Menu** opens with the following options: `1 Update system passphrase` /
  `2 Remove all encrypted data` / `3 Reboot` / `4 Logout`" (`:42-52`).

`[CERT-doc]` caveat recorded verbatim in the doc: "The following shows a **JACE-8000** shell connection.
**JACE-9000 message is similar.**" (`:30`) — so the exact JACE-9000 wording of this menu is a candidate for
live re-confirmation, but the option set is documented. Option 2 ("Remove all encrypted data") is
destructive; option 1 is the intended repair (re-enter the original controller's passphrase).

## §658.5 — Read-only takeaway & JACE-8000 contrast

For the operator's "read-only first" goal: the **entire boot/recovery surface in this block is off-limits to
casual exploration** — the Boot Options menu leads only to a credential reset or a normal boot; the button
leads to a wipe; the decrypt menu can remove data. The read-only surface of the JACE-9000 serial console is
confined to the ATLAS System Shell's **System Diagnostic submenu** [Block 657] §657.4 (and, once its live
numbering is confirmed, Ping Host).

Contrast with the sibling JACE-8000 ([Block 463]): the pre-boot menu shrank from **8 options → 2**, but the
**credential-recovery cryptography is unchanged** — a Tridium-signed, Host-id-bound, 24-hour-token
authorization that keeps station data, distinct from the button wipe that does not.
