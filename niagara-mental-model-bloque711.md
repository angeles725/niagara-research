## 711.1 — The two homes

[CERT]
- **`niagara_home`** — the Niagara SDK install (the `modules/` set you build against, the `devkit`, the
  gradle plugins under `$NIAGARA_HOME/etc/m2`). **Which SDK home is active selects the target version**
  (4.13/4.14/4.15) — version-targeting is by path ([Block 638]).
- **`niagara_user_home`** — the per-user home holding `security/keystore.jceks` (the signing keys). The
  niagara-signing plugin reads the signing key from HERE, not from a config block ([Block 639]).

## 711.2 — The gradle-niagara plugins

[CERT+INFER] Modules build with Tridium's gradle plugins (under `$NIAGARA_HOME/etc/m2`, applied in
`build.gradle.kts`):
- **`com.tridium.niagara-module`** (per part) — the module build: compiles, runs the `slotomatic` task, assembles
  the jar with its `META-INF/module.xml` manifest.
- **`com.tridium.niagara-signing`** — on the ROOT (registers a signing factory) + each part (signs the jar). No
  explicit `niagaraSigning{}` block; the `jar` task emerges already signed (`META-INF/*.SF/.RSA`) ([Block 639],
  [Block 632]).
- The task you invoke is `./gradlew :<part>:build` (or the deploy wrapper), with `:<part>:slotomatic` when needed.

## 711.3 — Slotomatic — the source-model code generator (NOT an annotation processor)

[CERT] Slotomatic (`devkit-wb` `com.tridium.slottool`) is the tool that turns your `@NiagaraType`/`@NiagaraProperty`
declarations into the generated slot code:
- It READS `module-include.xml` as an INPUT (`Slotomatic.java:140` resolves `modulePath/module-include.xml`) and
  parses `@Niagara*` via `NiagaraTypeProcessor` — a **JavaParser source-model builder, NOT a JSR-269 annotation
  processor** (there is no `Processor`/`AbstractProcessor` anywhere in the corpus) ([Block 631] §631.2).
- It WRITES the generated slot region back into your `.java` between `/*+ BEGIN BAJA AUTO GENERATED +*/` markers
  (`Compiler.write`, `Compiler.java:296-301`) — it does NOT write module-include.xml.
- It GUARDS: `Cannot update <file>; it is not in module-include.xml` (`Compiler.java:270`) — a class absent from
  `<type>` is not processed.

**Correction carried:** [Block 12] called module-include.xml "auto-generated by an annotation processor." It is
NOT — it is a hand-/wizard-authored INPUT that drives Slotomatic ([Block 631] §14).

## 711.4 — niagara-tools / ng-deploy.sh — the shop's deploy wrapper

[CERT] `niagara-tools` (v0.3.0) is NOT a build system, signer, or scaffolder — it is a cross-project **deploy
wrapper + knowledge base** ([Block 639] §639.3). Its `scripts/ng-deploy.sh` is the canonical deploy:
`backup → ./gradlew (mode A/B/C) → copy jars to STATION_MODULES_DIR → verify emitted types vs EXPECTED_*_TYPES`,
with phase exit codes 10/20/30/40/50 ([Block 637] §637.4). Because the security store lives on Windows, it uses
a **Robocopy WSL→Win→WSL** bridge for slotomatic + jar ([Block 639]).

## 711.5 — The Workbench devkit wizards

[CERT] The devkit wizards (e.g. `NewDriverWizard`) SCAFFOLD the artifacts: they create `module-include.xml` and
write `<type name= class=>` entries, generate the skeleton `.java`, and set up the part structure ([Block 631]
`NewDriverWizard.java`). After scaffolding, you author by hand + let Slotomatic fill the AUTO region.

## 711.6 — Tool → job map (runbook quick-reference)

[INFER]

| Tool | What it does | You invoke it |
|---|---|---|
| Workbench devkit wizard | scaffolds module + `module-include.xml` + `<type>` | once, at module creation |
| `@NiagaraType`/`@NiagaraProperty` | declares component types + slots in your `.java` | you write these |
| `module-include.xml` | the `<type>` list Slotomatic reads (drives codegen + registry) | you author/scaffold |
| Slotomatic (`:slotomatic`) | reads the above → writes the AUTO slot region in your `.java` | when a `@Niagara*` changed |
| `niagara-module` plugin | compile + jar + `META-INF/module.xml` | every `./gradlew build` |
| `niagara-signing` plugin | signs the jar from `niagara_user_home/security/keystore.jceks` | automatic in `jar` task |
| `ng-deploy.sh` | backup → gradlew → copy → verify types | to deploy to the station |
