## 590.1 Web: `BHierarchyBoxChannel` — JSON load/resolve over BOX [CERT]

`final class BHierarchyBoxChannel extends BBoxChannel` `[CERT] :23` (JSON over BOX, [Block 512]). Two commands
`[CERT] :36-40`:
- **`load`** `[CERT] :47-52` → `HierarchyServlet.load(path, contextParams, tags, …)` with the JSON fields
  `path`, `contextParams`, `tags` (all strings). This is the H5 stateless expansion over the web: the browser
  sends a node's `path` + its `contextParams` (the accumulated NEQL filter, [Block 588]) + `tags`, and gets the
  child elements back as JSON.
- **`resolve`** `[CERT] :57` → resolve a hierarchy ORD to an element.

So the web nav-tree UI never holds a server cursor — every expand is a `load` echoing that node's contextParams,
exactly the stateless model of [Block 588].

## 590.2 Cross-station: `BFoxHierarchyChannel` — one `getLevelElems` circuit [CERT]

`class BFoxHierarchyChannel extends BFoxChannel` `[CERT] :19`, channel name "hierarchy". `circuitOpened`
`[CERT] :34-38` dispatches ONE command, `getLevelElems`. `getLevelElems(circuit)` `[CERT] :42-56`:
```java
BFacets contextParams = BFacets.DEFAULT.decodeFromString(msg.getString("contextParams"));
BFacets tags          = BFacets.DEFAULT.decodeFromString(msg.getString("tags"));
String levelDefPath   = contextParams.gets("levelDefPath", "");
elems = levelDefPath.isEmpty() ? service.getHierarchyRootElems(getSessionContext())
                               : service.getChildElems(levelDefPath, contextParams, tags, getSessionContext());
ValueDocEncoder enc = new ValueDocEncoder(circuit.getOutputStream());  // stream the BLevelElem[] back
```
So a supervisor querying a subordinate's hierarchy opens a `getLevelElems` circuit, sends the node's
`contextParams` + `tags` (the H5 filter, with `levelDefPath` pulled from contextParams), and the subordinate runs
the SAME `BHierarchyService.getChildElems` and streams back the `BLevelElem[]` via `ValueDocEncoder`. This is the
remote path [Block 586] (scopes) and [Block 587] (scheme dispatch) route to.

## 590.3 `BFoxHierarchySpace` — a remote hierarchy that looks local [CERT]

`class BFoxHierarchySpace extends BHierarchySpace implements BIFoxProxySpace` `[CERT] :21` holds a
`BFoxHierarchyChannel channel` obtained from the Fox connection's registry
(`channels.get("hierarchy", BFoxHierarchyChannel.TYPE)` `[CERT] :54-55`). So a subordinate's hierarchy is
mounted as a local `BHierarchySpace` that PROXIES every operation over the "hierarchy" Fox channel — which is
exactly what [Block 587] §587.2's `instanceof BFoxHierarchySpace` dispatch detects. A `hierarchy:` ORD against a
remote station transparently rides this proxy.

## 590.4 Focus close — the hierarchy engine, end to end [CERT-synthesis]

With H7 the `hierarchy` focus is complete. The engine, across seven blocks: a hierarchy is a TREE of level defs
(root `BHierarchy`), each level a GROUP (tag/list folder) or ENTITY (query/relation leaf) ([Block 584]); the tree
is generated by running each level's NEQL, either ON-DEMAND with the filter carried in `contextParams` ([Block
588]) or from a JOB-BUILT server CACHE ([Block 585]); queries fan across licensed SCOPES on a CPUs×8 ForkJoinPool
([Block 586]); category permissions are baked up the tree and filtered per-user at read ([Block 589]); the tree
is addressable via the `hierarchy:` `BSpaceScheme` whose leaf dereferences to the real component ([Block 587]);
and it is reachable identically from the local nav tree, a web browser (BOX), and a remote station (Fox) — all
carrying the same stateless `contextParams` (this block). It is a coherent, well-factored virtual-navigation
engine layered cleanly on tags/NEQL and the category RBAC model.
