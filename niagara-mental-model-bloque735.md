## 735.1 — How a slot is declared `[CERT, cites B4/module-anatomy]`

Frozen slots are declared as annotations on the class and generated by Slot-o-Matic:
- `@NiagaraType` on the class; `@NiagaraProperty(name, type, defaultValue, flags, facets)`,
  `@NiagaraAction(name, parameterType, flags)`, `@NiagaraTopic(name, eventType, flags)` per slot.
- Slotomatic writes the AUTO region: `public static final Property x = newProperty(flags, default, facets);`
  + `getX()`/`setX()`; for actions `newAction(...)` + `doX()`; for topics `newTopic(...)` + `fireX()`.
- **Frozen** = declared in the type (fixed, every instance has them). **Dynamic** = added at runtime with
  `add()`/`addProperty()`, removable, reorderable (`reorder(Property[])`). (B4 §4.1, §4.3.3.)

## 735.2 — Facets (units / precision / range / …) `[CERT]`

A facet set is a `BFacets` (a `BStruct` of key→value). Declared on a property via `facets = @Facet("…")` or
`newProperty(flags, default, BFacets.make…)`; e.g. `newProperty(0, 3, BFacets.makeInt(null, 2, 10))`
(min 2, max 10) — `BSequence.java:54,275`. Factory helpers: `BFacets.makeInt/makeNumeric/makeBoolean/make(key,val)`.

Key set (`BFacets.java`) — the ones that matter for control:
- **`units`** (:86) — a `BUnit` (°C, kPa, %, …); **`unitConversion`** (:159), **`showUnits`** (:166).
- **`precision`** (:83) — decimal places; **`radix`** (:89); **`showSeparators`** (:170); **`forceSign`** (:180).
- **`min`/`max`** (:65/72) — numeric range (the field editor enforces it; still clamp in code — B730 §730.6);
  **`range`** (:92) — the `BEnumRange`/frozen enum for enum slots; **`trueText`/`falseText`** (:76/80) — boolean labels.
- **`allowNull`** (:119); time facets `showDate/showTime/showSeconds/…` (:95-107); **`fieldWidth`/`multiLine`** (:113/116).
- Editor overrides: **`fieldEditor`** (:129, WB), **`uxFieldEditor`** (:138, browser), `inplaceEditor`, `cellEditor`.
- Writable-specific: **`maxOverrideDuration`** (:200).

**Dynamic facet projection**: override `getSlotFacets(Slot)` (`BComplex.java:451`) to compute a slot's facets
at runtime — e.g. project one `facets` config slot's units/precision onto every output (B730 §730.6;
`BSequence.getSlotFacets:894`). `toString(getSlotFacets(prop))` is how a value renders with its facets
(`BComplex.java:486-490`).

## 735.3 — `proxyExt` (the field binding) `[CERT, cites B734]`

On a `BControlPoint`, `proxyExt` (`BAbstractProxyExt`, default `BNullProxyExt`) is the binding to a field
device; ≠ NullProxyExt → a proxy point (field IO, async — B730 §730.8); == NullProxyExt → a local logic
point (B734 §734.4). Our custom components don't have `proxyExt` (they're not points) — they BLink to proxy
points instead (B734 §734.5).

## 735.4 — WHY not every slot appears at Link Mark `[CERT]`

Five layered filters decide what the link picker offers/accepts:

1. **Kind + type compatibility** — links are Property→Property (a "dataLink", `BLink.relationId` default
   `n:dataLink`) or Topic→Action (event link); and the value types must be compatible. `BComponent.checkLink
   (source, sourceSlot, targetSlot, cx)` (`BComponent.java:1580`) "does standard checking, then routes to
   `doCheckLink()`" and returns a `LinkCheck`; `BLink.activate()` enforces it. So an incompatible pair is
   never a valid target.
2. **`Flags.HIDDEN`** (0x04, 'h') — removes the slot from the everyday UI, including the property sheet and
   the link picker. This is the main lever for internal slots (timer-expiry actions, computed
   intermediates). (Visibility, not permission — B268/B4.)
3. **`Flags.SUMMARY`** (0x08, 's') — the slots shown as **pins on the wire sheet** (the default, at-a-glance
   linking surface). Non-summary slots still exist and can be linked via the fuller Link dialog, but they
   don't clutter the wire sheet. So SUMMARY curates the *common* link surface; HIDDEN removes from *all* of it.
4. **Marker interfaces (the precise exclusion)** — enforced in `checkLink` + `BLink.activate`:
   - `BIUnlinkable` — the type can NEVER be a link source OR target.
   - `BIUnlinkableSource` — the type can never be a link SOURCE.
   - `BIUnlinkableSlotsContainer` — a component declares SPECIFIC CHILD SLOTS that can never be source
     and/or target (fine-grained, per-slot). This is the exact tool to keep chosen slots out of the picker
     without hiding them from the property sheet.
5. **`doCheckLink()` override** — a component can add custom link rules (reject certain pairs) beyond the
   standard type check.

## 735.5 — Application to our modules `[INFER]`
- We ALREADY use `Flags.HIDDEN` on internal actions (`intervalExpired`/`durationExpired`/… in
  BDefrostController; timer actions in BEvaporatorUnit/BCompressorControl) → they don't appear in the link
  picker or property sheet. Correct.
- `Flags.SUMMARY` on the real I/O (`runCmd`, `valveOut`, `coilTemp`, setpoints) keeps the wire sheet to the
  meaningful pins; keep interim state non-summary or hidden.
- If a slot must be VISIBLE in the property sheet but never LINKED (e.g., an operator-only tunable that
  should never be driven by a link), implement `BIUnlinkableSlotsContainer` and name it — cleaner than
  HIDDEN (which would also remove it from the property sheet).
- Facets: put `units`/`precision` on our temp/pressure/percent slots (today many are bare doubles) so the HMI
  and links show engineering units; use `getSlotFacets` to project one config onto repeated outputs.
